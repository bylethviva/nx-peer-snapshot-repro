# Nx pnpm peer snapshot reproduction

This is a public-package-only serializer reproduction against **Nx 23.2.1**.
It calls the published package's real `stringifyPnpmLockfile` implementation
without modifying Nx. The fixture lockfile was generated by **pnpm 10.18.3**
from the two included public Nest manifests. Verified on **Node 24.19.0**.

## Run

Use Node 24 or newer and pnpm 10.18.3 (via Corepack or an existing install):

```sh
pnpm install --frozen-lockfile --registry=https://registry.npmjs.org
pnpm diagnose
pnpm test
```

`pnpm diagnose` exits **0** when it confirms the known unpatched bug.
`pnpm test` exits **1** on Nx 23.2.1 because it asserts the correct behavior:
Nx must preserve the exact root importer reference in both snapshot orders.
After a correct upstream fix, the same correctness command must exit **0**.
For direct execution, use `node reproduce.cjs --diagnose` or
`node reproduce.cjs --assert`.

The normal fixture's root importer uses Nest core **11.1.6** with
`reflect-metadata@0.2.2`. Another importer uses the same Nest core version
with `reflect-metadata@0.2.1`. Both are valid peer contexts. Nx selects the
**0.2.1** peer context for the root; reversing only the `snapshots` object's
insertion order causes it to select the correct **0.2.2** context. The root
importer, manifests, package versions and graph stay identical.

## Scope

The lockfile is a real pnpm-generated fixture with public registry integrity
hashes. The external graph is deliberately constructed: one node per package
base version, including the full public dependency closure. This isolates the
serializer's loss of importer identity. There is no Nx workspace discovery,
application build, isolated Nest installation, or scheduler startup in this
reproduction. It demonstrates changed serialized resolution, not runtime
class identity or an application failure.

The reproduction package depends only on the pinned public Nx package. Nest
packages appear only in the committed fixture lockfile; they need not be
installed to run the serializer. No private files, registries or credentials
are required.

## Fixture provenance

The fixture pins `@nestjs/common` and `@nestjs/core` to 11.1.6, `rxjs` to
7.8.2, and `reflect-metadata` to 0.2.2 at the root and 0.2.1 in `other`.
Regenerate it with pnpm 10.18.3:

```sh
cd fixtures/source
pnpm install --lockfile-only --registry=https://registry.npmjs.org
```

The included lockfile also fixes all transitive versions. Regeneration may
change transitive resolutions over time; it is unnecessary for reproduction.

## Validate a later fix

To test a compiled upstream parser with the same fixture and assertions:

```sh
NX_PNPM_PARSER=/absolute/path/to/compiled/pnpm-parser.js node reproduce.cjs --assert
```

The replacement parser must be runnable CommonJS with its Nx sibling modules
and dependencies available. This option does not patch or replace the pinned
public Nx control. `--diagnose` intentionally checks the old bug and therefore
should fail against a fixed parser.
